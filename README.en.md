# FlowerWall · 花墙

A Windows desktop wallpaper that visualises whatever your computer is playing:
**a spinning vinyl record with a spectrum ring around it**, rendered live from
system audio, with a full-screen background.

[中文说明](README.md) ｜ **English**

- **Stack**: C# 12 / .NET 8, WinForms (windows & message loop) + WPF (drawing), **zero third-party dependencies**
- **Audio**: WASAPI loopback — captures what the system plays, no virtual cable, no echo
- **Rendering**: one screen-sized layered window (`UpdateLayeredWindow`, per-pixel alpha), sitting above the wallpaper and below the desktop icons
- **Wake-up**: click the plum blossom at the screen edge, or let it fade in after 5 minutes of idle
- **Bilingual UI**: switch between 花墙 and FlowerWall at runtime
- **Default palette**: matcha green `#A9C69A` + sakura pink `#E4679A`, with 5 more presets one click away

## Quick start

### 1. Install the .NET 8 SDK (once)

```powershell
powershell -ExecutionPolicy Bypass -File scripts\bootstrap-sdk.ps1
```

Installs into the project-local `.tools\dotnet`. No admin rights, nothing written
outside the repo. The script is idempotent.

### 2. Run

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 run
```

### 3. Build a single-file release

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 publish      # self-contained, no .NET needed on the target
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 publish-fd   # framework-dependent, much smaller
```

> The first publish needs network access: `-r win-x64` triggers a restore of the
> win-x64 runtime packs. Offline you will get `NU1301` — run it once on a machine
> that can reach nuget.org and the packs stay in the local cache afterwards.

## Usage

| Action | Result |
| --- | --- |
| Left-click the plum blossom at the screen edge | Show / hide the wallpaper |
| Drag the blossom | Move it; it snaps when released near an edge |
| Hover the blossom | Grows, brightens, gains an outer glow |
| Right-click the blossom or the tray icon | Menu: show, import background, reset background, colour scheme, language, reload config, open config, exit |
| 5 minutes without mouse or keyboard | Fades in automatically (boosted mode) |
| Any input afterwards | Fades out (stays if you had opened it manually) |

Desktop icons are hidden while the wallpaper is visible and restored as soon as it
fades out. Exiting the app always restores them, including on an unhandled exception.

### Colour schemes

Right-click → **Color scheme** offers five presets that swap background, accent,
highlight and groove colours together:

| Preset | Background | Accent |
| --- | --- | --- |
| `Matcha` (default) | matcha green `#A9C69A` | sakura pink `#E4679A` |
| `Forest` | deep forest `#20463A` | mint `#5FD6A8` |
| `Paper` | off-white `#F4F1EA` | ruby `#D6336C` |
| `Midnight` | dark violet `#211C2E` | violet `#A78BFA` |
| `Sakura` | sakura pink `#F2D3DE` | bright pink `#E85D9B` |

Fine-tuning is still just editing `theme.*` / `background.*` in the config file —
afterwards the menu shows *Custom (edited colors)* instead of a preset name.

### Background

- **Import background image** — pick a file; it is copied into `assets\` and wired into the config.
- **Reset to default background** — returns to the flat colour.
  (Editing `background.color` alone does *not* work while an image is set — the image wins.
  That is the single easiest trap in the config.)

## Configuration

`config/settings.json`. The **Reload config** menu item applies changes without a restart.
The file starts with a comment block listing the common knobs, and `//` / `/* */` are supported.

After adding a field in code, re-sync the template with:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 diag -DiagArgs config
```

| What | Field |
| --- | --- |
| Whole palette | tray menu, or `theme.preset` |
| Background colour | `background.color` |
| Background depth | `background.gradientStrength` (**0 = flat colour**; a gradient costs a lot at full screen) |
| Background image / reset | tray menu |
| Record size / speed | `record.diameter` / `record.rpm` |
| Record grooves | `record.grooveCount`, `record.grooveOpacity`, `record.grooveOuterBoost` |
| Record gloss / wear | `record.specularStrength` / `record.wearStrength` |
| Centre text size | `record.centerTextScale` |
| Spectrum bars | `spectrum.bandCount` / `spectrum.barWidth` / `spectrum.maxLength` |
| Sensitivity | `spectrum.gain`, `spectrum.noiseFloorDb`, `spectrum.ceilingDb` |
| Frame rate | `render.maxFps` (default 24) |
| Idle wake-up | `idle.thresholdMinutes`, `idle.boostWhenIdle` |
| UI language | `app.language`: `Auto` / `Chinese` / `English` |

## Performance

Measured on this machine, reproducible: `scripts\build.ps1 diag -DiagArgs render` reports per-stage
timings; running the app with `FLOWERWALL_STATS=1` writes one line per second to
`logs\stats.log`.

The background fills the whole screen, so the canvas equals the screen resolution
and per-frame cost scales with it (numbers below are 1920×1080). Expect ±1 ms of
run-to-run noise — read the trend, not the last digit:

| Stage | Cost |
| --- | --- |
| Clear | 0.9 ms/frame |
| Flat background | 2.4 ms/frame |
| Vinyl (halo + disc + centre layer) | 11.6 ms/frame |
| Sound-wave ring (main + secondary + reflection + glow) | 6.4 ms/frame |
| Draw only | 18.1 ms/frame (55 FPS ceiling) |
| **Whole frame (including pixel blit)** | **≈ 21.6 ms/frame (46 FPS ceiling)** |

`render.maxFps` defaults to 24, so the whole frame above uses about **52%** of the
24 FPS budget; the headroom covers idle boost and large imported background images.

Runtime:

| State | CPU | Memory |
| --- | --- | --- |
| Hidden (waiting to wake) | **0.0%** | ~66 MB |
| Visible | ~40–60% of one core | ~110 MB |
| Visible but silent and the record has stopped | **0.0%** | — |

Notes:

- Hidden means `Hide()` and no drawing at all — the CPU really is zero, not "almost".
- All ~20 ms comes from CPU software rasterisation. On real hardware WPF uses the GPU,
  so expect lower numbers there.
- **`maxFps` is a ceiling, not a promise**: actual ≈ 1 / (timer granularity + frame cost).
  This sandbox has coarse timer granularity; a real desktop session gets closer to the configured value.
- The spectrum is **discrete bars** and does not depend on time, so once the record stops
  in silence the app stops redrawing entirely.

## Project layout

```
FlowerWall/
├─ src/
│  ├─ FlowerWall.Core/           library: shared by the app, the diagnostics tool and tests
│  │  ├─ Audio/                  loopback capture, ring buffer, FFT, band analysis
│  │  ├─ Core/                   config model/IO, localisation, idle detection, state machine
│  │  ├─ Interop/                Win32 and WASAPI declarations (declarations only)
│  │  └─ Rendering/              background, vinyl, spectrum bars, blossom geometry
│  └─ FlowerWall.Desktop/        the app: entry point, windows, floating blossom, tray
├─ tools/FlowerWall.Diagnostics/ offline measurements, preview export, config template
├─ config/settings.json          user configuration
├─ artifacts/                    previews produced by the diagnostics tool
├─ docs/                         architecture notes, images
└─ scripts/                      build scripts (see scripts/README.md)
```

Three projects, because the logic layer has no dependency on any window: it can be
measured and regression-tested headlessly, while the desktop project only shows state
and collects input.

## Contributing conventions

- **Zero third-party dependencies.** Before adding a NuGet package, check whether it is
  really necessary, and record the reason in `docs/design.md`.
- **Configuration first.** Every visual or behavioural parameter lives in `AppConfig`;
  no magic numbers in drawing code.
- **Separate rendering from data.** `Rendering/` only consumes `SpectrumFrame`; it never
  reads audio or touches a window.
- **Pre-rasterise static graphics.** Complex static geometry left in the per-frame scene
  graph is re-rasterised every frame — measured 3× slower.
- **Contrast is what makes dark detail visible.** "The parameter is set" does not mean
  "you can see it". Always check the 2× zoom preview (`preview-vinyl-closeup.png`).
- **Zero allocations per frame.** No `new` on the render or analysis paths.
- **Run the diagnostics** after changes: `scripts\build.ps1 diag`.
